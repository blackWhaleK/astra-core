## 已确认并落入候选稿

- **M1 职责与协作（§4.1.1）。** 新调用由调用方明确提供场景标识和版本号。M1 保留各版本记录，查找指定版本、校验输入并将编排交给 M2。指定版本不存在时，M1 在入口返回提示。人工反馈关联原 Execution，并沿用启动时的编排。
- **M1 核心对象（§4.1.2）。** SceneDefinition、SceneVersion 描述场景及版本。SceneManagementService 登记和查询，SceneInvocationService 对外提供 start、reply、cancel。SceneRequest 与 SceneResponse 表达请求及响应，一次 Execution 可关联多次请求。
- **M1 服务接口契约（§4.1.3）。** 管理服务先登记场景再登记版本，同一版本不可覆盖。调用服务按指定版本发起调用，按追问关联回复，按目标执行处理取消。
- **M1 对象关系与执行流程（§4.1.4）。** 六个对象的协作按装配场景、发起调用、按需回复或取消、交付结果四步说明。
- **M1 运行规则、参数与验证（§4.1.5）。** 已确认参数来源和七组验证预期，涵盖版本登记、入口校验、回复去重、会话忙时与过期、归属校验、取消目标和结果交付。实际接入验证尚未执行。
- **M2 已有运行契约（§4.2）。** Session、Execution、Node 的协作及接口见 §4.2.1—§4.2.7。§4.2.8 已完成首期运行规则、参数及七项验证预期，覆盖人工反馈、循环和 Agent 限制、超时、重试、并行汇聚、刷新与结果交付。8 小时用于会话空闲有效期，实际运行时限可配置。刷新或重连后凭本地会话标识查询后端状态，归属匹配且有效时续用；查无会话时新调用按首次执行处理，SSE 单纯断线由原 Execution 按生命周期继续推进。
