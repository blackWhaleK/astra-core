# 任务提案 · M1_DESIGN

BlackWhaleK 已确认两个服务的接口契约。以下保留讨论时的提案和取舍，落稿文字见[候选说明书 §4.1.3](../../../docs/baseline/specificationV2.md#413-场景服务接口契约)。传输格式留待后续设计。

## 目标与依据

依据[说明书](../../../docs/baseline/specificationV2.md) §4.1.1—§4.1.2，三个操作均经 `SceneInvocationService` 接入，以 `SceneRequest` 表达输入，以 `SceneResponse` 交付响应。`start` 通过 `SceneManagementService` 按 `SceneDefinition` 的场景标识和指定版本号取得 `SceneVersion`。M1 校验输入、交付编排、组织响应，M2 管理 Session 与 Execution 并决定运行结果。

## 候选修订

| 操作与依据 | 已有约定 | 建议的调用方输入与 M1→M2 交付 | 建议的调用方响应与影响 | 提案提出时的状态 |
| --- | --- | --- | --- | --- |
| `start` · P-001、P-002 | 每次新调用显式指定场景和版本，指定版本不存在时在入口结束。 | 调用方提供场景标识、版本号及该版本要求的文本或文件。首次调用省略 `sessionId`；多轮会话中的下一问显式携带原 `sessionId`。M1 交付指定版本的编排、已校验输入、可信上下文及适用的会话关联。 | M2 建立执行后，M1 尽早返回 `sessionId` 和 `executionId`，使调用方在最终输出前可以取消。后续按版本交付追问、结果或结束原因。输入有误或版本不存在时返回入口提示；已有执行未结束时转达忙时提示；显式携带失效会话时提示重新发起。 | 待确认 |
| `reply` · P-002、P-003 | 当前追问的有效回复续接原执行，重复回复只生效一次。 | 建议携带 `sessionId`、`executionId`、`promptId`、`replyId` 及补充文本或选项。M1 将关联标识、内容及可信上下文交给 M2；由 M2 核对归属、当前执行、当前追问及回复是否重复。同一次回复重试沿用同一 `replyId`。 | 追问响应给出会话、执行、追问标识及待补内容或选项。有效回复沿用原版本，返回下一条追问、结果或结束原因；针对旧追问的回复提示追问已失效，当前执行保持原进度。 | 待确认 |
| `cancel` · P-002、P-003 | 调用方显式取消目标执行，M2 确定终态。 | 建议携带 `sessionId` 和 `executionId`。M1 连同可信上下文交给 M2 核对归属和目标；旧请求即使晚于下一次执行到达，也只能指向原目标。 | 已确认取消时返回取消原因；若完成先于取消生效，已有终态保持有效。目标已结束且可识别时提示已结束，状态已清理时按可用信息提示目标不可用。 | 待确认 |

三个操作均建议由接入侧从已认证的调用环境取得可信身份。调用方提交的业务文本和关联标识用于提供输入、定位目标；服务端依据可信上下文核对归属后再操作。

### 用场景核对

- F-002 的“本月福州分行离职率”发起执行 A。A 询问指标口径时，选择口径用 `reply` 指回 A 的这次追问。A 结束后的“去年同期呢”用 `start` 带原会话、场景和版本，创建执行 B。若此时收到取消 A 的旧请求，B 继续运行。
- F-003 上传 Word 后，调用方要在报告分析期间取消，需要先取得本次执行的关联标识。完整检查结果仍通过原调用交付。按 §4.2.8.5，错过最终输出可重新发起独立处理；单纯断流时原执行继续按自身生命周期推进。

## 提交确认时的三个问题

1. 是否采用“首次省略 `sessionId`、同一多轮会话的下一问显式携带”的约定？显式携带但已过期时，沿用基线的“会话已失效，请重新发起”。
2. 回复是否显式携带 `executionId`？建议携带，旧页面误回时能直接核对目标。较简方案由服务端按会话定位当前执行，再严格匹配追问及回复标识。
3. 取消是否显式携带会话与执行两个标识，并在执行建立后、最终输出前交付这两个标识？这样一次性场景也能在运行中取消。具体 HTTP 路径、响应头或 SSE 事件形式可另议。

## §4.1.3 替换稿（审阅记录）

同一版本不可覆盖、先登记场景、相同内容重复登记返回成功及同一场景标识下的定义冲突处理均已确认。以下保留本轮提案，确认依据见[任务纪要](notes.md)。

#### 4.1.3 场景服务接口契约

##### 4.1.3.1 场景管理服务 `SceneManagementService`（P-001）

业务扩展装配时，通过管理服务登记场景定义及其版本。调用服务发起新执行时，通过管理服务取得调用方指定的版本。

| 操作 | 输入与返回 | 处理规则 |
| --- | --- | --- |
| `registerScene(definition)` 登记场景 | 接收 `SceneDefinition`，按场景标识登记，返回登记结果。 | 同一标识、相同定义重复登记时，返回成功并保留原记录。定义不同时，返回场景定义冲突。 |
| `registerVersion(version)` 登记版本 | 接收 `SceneVersion`，按场景标识和版本号登记调用方式、输入输出契约及编排，返回登记结果。 | 先登记所属场景。场景不存在时，登记失败。同一版本内容完全相同，重复登记返回成功并保留原记录；内容不同，拒绝登记并返回版本冲突。 |
| `getVersion(sceneId, version)` 查询版本 | 按场景标识和版本号精确查询。找到时返回对应的 `SceneVersion`，否则返回未找到。 | 调用服务只使用请求指定的版本。查询未命中时，调用在 M1 入口结束。 |

**同一场景下，已登记的版本不允许覆盖。** 调用方式、输入输出契约或编排发生变化时，须使用新版本号登记。例如，登记 `F-002 / v2` 后，显式请求 `F-002 / v1` 仍取得原来的契约和编排。

##### 4.1.3.2 场景调用服务 `SceneInvocationService`（P-002、P-003）

调用方通过 `SceneRequest` 表达本次操作，M1 通过 `SceneResponse` 交付关联标识、追问、业务结果或结束原因。M1 从已认证的调用环境取得可信身份，连同请求关联信息交给 M2。涉及已有会话时，M2 先校验会话归属，再核对相应的执行或追问。

| 操作 | 调用方提供 | 处理与返回 |
| --- | --- | --- |
| `start` 发起独立调用 | 场景标识、版本号及业务输入。首次调用省略 `sessionId`，同一多轮会话的下一问携带原 `sessionId`。 | M1 查询指定版本、校验输入，将编排和本次输入交给 M2。版本不存在或输入不合约时返回入口提示。会话已有未结束执行时返回忙时提示，会话已过期时提示“会话已失效，请重新发起”。M2 创建执行后，M1 在最终输出前尽早交付 `sessionId` 和 `executionId`，供回复或运行中取消使用。 |
| `reply` 回答当前追问 | 追问响应中的 `sessionId`、`executionId`、`promptId`，以及本次回答的 `replyId` 和补充文本或所选选项。重试同一回答时复用 `replyId`。 | M2 核对当前执行和追问，同一回答只生效一次。有效回复沿用原执行及其启动版本。仍需补充时，M1 返回追问标识和待补内容或选项；执行结束时，返回结果或结束原因。针对旧追问的回复收到失效提示，当前执行保持原进度。 |
| `cancel` 取消目标执行 | `sessionId` 和目标 `executionId`。 | M2 核对目标后处理运行中或等待输入的执行，确认取消后由 M1 返回结束原因。目标已结束且仍可识别时提示已结束，保留原终态；目标状态已清理时提示目标不可用。迟到的取消请求只作用于原目标。 |

例如，F-002 追问指标口径时，用户选择口径用 `reply` 续接本次查询。结果交付后再问“去年同期呢”，用 `start` 在同一有效会话中创建新执行。F-001、F-003 的结果通过原调用交付，断流处理见 §4.2.8.5。具体 HTTP 路径、字段编码和 SSE 事件格式留待传输设计。

## §4.1.4 讨论稿（已确认落稿）

#### 4.1.4 核心对象关联关系与执行流程

一个 `SceneDefinition` 可对应多个 `SceneVersion`，由 `SceneManagementService` 登记和查询。`SceneInvocationService` 接收调用方的 `SceneRequest`，发起新执行时向管理服务查询指定版本，并通过 `SceneResponse` 向调用方交付追问、结果或结束原因。

1. **装配场景。** 业务扩展装配时，先登记场景定义，再登记该场景的版本及编排。
2. **发起调用。** 调用方通过 `start` 指定场景和版本。M1 按该版本校验输入，将编排、输入和可信上下文交给 M2。M2 创建执行后，M1 将会话和执行标识交给调用方。
3. **处理反馈或取消。** 需要补充信息时，M1 将 M2 的追问交给调用方，后续 `reply` 关联原执行和当前追问，M2 按启动时的版本继续处理。调用方也可通过 `cancel` 指定要取消的执行，由 M2 核对目标并处理。
4. **交付结果。** M2 确定执行结果或结束原因后，M1 按本次场景版本的输出契约返回给调用方。

## §4.1.5 讨论稿（已确认落稿）

#### 4.1.5 运行规则、参数与验证

本节细化 P-001—P-003，验证两个服务在装配、发起调用和交付结果时可观察的行为。

**运行规则。** 先登记场景，再登记版本。相同内容重复登记返回成功并保留原记录，同一版本的内容发生变化须登记新版本号。每次 `start` 只使用调用方指定的版本，查找版本或校验输入失败时，本次请求在 M1 结束。执行建立后，M1 在最终输出前交付会话和执行标识；后续追问、业务结果和结束原因按启动版本的输出契约交付。M2 核对会话归属、执行及追问关联，M1 向调用方返回相应结果。

**参数与来源。** 调用方式（一次性或多轮）、输入契约、输出契约及编排取自 `SceneVersion`。场景标识和版本号由调用方在 `start` 时指定；会话、执行、追问和回复标识按 §4.1.3.2 随相应操作传递。可信身份由接入环境提供。执行时限、轮次及依赖重试上限沿用 §4.2.8 的规定。连续 8 小时无有效对话后，续接状态过期，M1 向调用方提示“会话已失效，请重新发起”。

**验证预期。** 下列场景供后续接入验证使用，当前仅完成文档核对。

| 验证场景 | 预期行为 |
| --- | --- |
| 登记 `F-002 / v1` 后再次登记，随后增加 `v2` | 重复提交相同内容返回成功且不写入；同号不同内容返回版本冲突。登记 `v2` 后按 `v1` 查询仍取得原契约和编排。 |
| `start` 指定不存在的版本，或输入不符合指定版本的契约 | M1 返回相应入口提示，两种情况创建的 Execution 数均为零。 |
| F-002 在执行 A 中追问口径，调用方重复发送同一 `replyId` | 有效回答只推进 A 一次。A 结束后在原会话发起下一问，创建执行 B；此时回答 A 的旧追问，不推进 B。 |
| 同一会话仍在执行时发起独立问题；会话过期后携带原标识再次发起 | 前者返回当前执行尚未结束的提示，后者返回会话失效提示。两次请求均不创建新执行。 |
| 调用方携带其他用户的会话和执行标识进行回复或取消 | M2 的归属校验拒绝操作，目标执行保持原状态，调用方无法取得目标会话的追问或结果。 |
| F-003 分析期间显式取消；同一多轮会话中取消旧执行 A 的请求晚于执行 B 到达 | 前者可使用最终结果交付前取得的标识取消目标执行，确认取消后收到结束原因。后者只指向 A，B 继续运行。 |
| F-001、F-003 正常结束，或在最终输出前发生 SSE 断流 | 正常时通过原调用交付符合指定版本契约的结果。断流本身不触发取消；错过结果后可重新发起独立处理，首期不提供短时结果补取。 |
