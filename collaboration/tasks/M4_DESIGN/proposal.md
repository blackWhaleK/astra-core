更新于 2026-11-26，负责人 BlackWhaleK。§4.4.1 引自[当前候选说明书](../../../docs/baseline/specificationV2.md)。§4.4.2—§4.4.5 是拟议正文，沿用已确认的调用路径、职责和业务结果。已确认工具不设版本，编排文件按版本管理。其余新增对象、操作、运行细则及验证预期供审阅。验证均未执行。

### 4.4 工具与业务连接

#### 4.4.1 职责与协作

M4 向场景提供统一的工具登记和调用能力。编排决定工具调用由谁发起，两条路径共用工具契约、校验和领域实现。

| 调用路径 | 发起与返回 |
| --- | --- |
| M2 → M4 | 编排指定工具时，M2 的 TOOL 节点携带工具引用、业务参数和可信上下文调用 M4。M4 返回业务结果或调用错误，M2 按编排决定后续步骤。 |
| M3 → M4 | 受控 AGENT 节点允许模型自主调用时，模型可以从本轮允许的工具中选择并发起请求。M3 内的 Spring AI 回调可直接调用 M4，并接收工具结果。需要模型继续作答时，由 M3 将结果与对应的工具请求关联后交给模型。Agent 的轮次、终止条件和 Execution 状态由 M2 按 P-007、§4.2.8 管理。 |

| 环节 | M4 职责 | 协作方职责 |
| --- | --- | --- |
| 登记与引用（P-011） | 登记工具用途、参数、结果契约及对应实现，提供场景可引用的工具说明。 | 领域扩展提供契约和具体工具，M7 装配扩展，M1 管理引用工具的场景版本。 |
| 调用边界（P-013） | 每次调用都核对工具是否在场景允许的范围内，按契约校验参数，并将运行上下文中的可信身份与业务参数分别传给领域扩展。 | 领域扩展将身份和目标业务对象交给原系统鉴权。原系统判断调用人能否执行该操作。 |
| 调用与结果（P-012） | 调用已登记的实现，向调用方返回业务结果或调用错误，并提供与本次执行关联的调用信号。 | 领域扩展负责字段映射、原系统接口调用和响应转换。原系统维护业务事实和规则。M6 使用调用信号做追踪和审计，M1 按场景输出契约交付最终结果。 |

以 F-001 为例，甲替乙请假时，甲是经认证的调用人，乙是余额查询的目标。若原系统明确拒绝甲查询乙的余额，场景结束本次办理，Execution 记为 `SUCCEEDED`，向甲提示“无权查询该人员的请假余额”。此次查询不重试，不生成请假页面。

工具调用的具体接口、需要人工确认的操作、幂等处理及结果核对规则待设计。Spring AI 工具回调与公司模型网关、原系统授权接口的实际接入待验证。

#### 4.4.2 核心数据模型与对象

工具在领域扩展中定义并实现，在场景版本的编排中引用。两条调用路径共用下列六个对象或契约。

| 对象或契约 | 归属及职责 | 核心信息或操作 |
| --- | --- | --- |
| `ToolContract` 工具契约 | M4 约定描述方式，领域扩展提供每个工具的定义。供编排引用、参数校验和结果解释共同使用。 | 工具标识、用途、输入结构和结果约定。模型可见的工具名、说明和输入结构从这份契约取得。 |
| `ToolHandler` 领域工具执行接口 | M4 约定执行入口，领域扩展提供实现。例如人力扩展在 `extensions/hr/tool` 中实现余额查询，使用 `extensions/hr/client` 对接业务和授权接口。 | 接收已通过工具契约校验的参数及所需可信上下文，映射原系统请求，将响应转换成契约约定的业务结果或调用错误。业务事实和授权决定由原系统提供。 |
| `ToolRegistry` 工具注册表 | M4 在 M7 装配领域扩展时，按工具标识登记契约及对应的执行实现。 | 按编排引用取得契约或定位实现。已登记的工具中，本节点允许哪些由当前编排给出。 |
| `ToolCallRequest` 工具调用请求 | 表达一次实际调用，两条路径共用。 | 工具引用和业务参数，以及来自运行环境的当前节点工具范围和必要的 `NodeContext` 信息，包括可信身份、执行与节点调用标识、适用时限及取消信号。 |
| `ToolInvocationService` 工具调用服务 | M4 向 M2 和 M3 回调提供统一入口。 | 检查引用是否属于当前节点允许范围，查找契约和实现，校验参数后执行。越界、查无工具或参数无效时，返回调用错误，在调用领域实现前结束。提供与本次执行关联的调用信号供 M6 使用。 |
| `ToolCallResult` 工具调用结果 | M4 向本次调用方交回业务结果或调用错误。 | 业务结果依工具契约表达，例如余额或明确的授权拒绝。依赖超时等调用错误携带可供场景判断的原因。Execution 终态由 M2 依据场景规则确定。 |

TOOL 节点在编排文件里填写工具标识，允许自主调用的 AGENT 节点填写允许使用的工具标识集合。M2 从本次执行采用的编排文件版本取得这些配置。M4 根据同一范围提供说明并检查实际请求，节点无需在 M4 再登记一份绑定。

#### 4.4.3 工具注册与调用接口契约

下列操作描述输入、输出和失败条件，具体名称供审阅。

| 操作 | 调用方及输入 | 返回与处理 |
| --- | --- | --- |
| `ToolRegistry.register(contract, handler)` | M7 装配领域扩展时，提交工具契约及其实现。 | 登记后可按引用取得两者。建议同一引用对应一份契约和一个实现。发生冲突时报告引用冲突，保留已登记项。 |
| `ToolRegistry.describe(refs)` | 场景版本登记方传入节点引用，或运行方传入本轮允许的集合。 | 返回对应的工具说明，缺失时指出具体引用。建议登记编排时指出缺失标识及所在节点，并拒绝本次登记。 |
| `ToolInvocationService.invoke(request)` | M2 的 TOOL 节点或 M3 的 Spring AI 回调，传入工具引用、业务参数及可信运行信息。 | 核对当前范围、引用和参数。通过后定位处理器，交回一个 ToolCallResult。范围越界、参数无效、可信身份缺失时结束此次调用，原系统调用数为零。 |
| `ToolHandler.execute(arguments, context)` | M4 调用领域实现，提供已校验参数及本次所需的可信上下文。 | 领域实现完成原系统鉴权、参数映射和调用，将有效响应转成契约约定的结果；超时或响应无法按契约解释时返回带原因的调用错误。 |

**编排与工具引用（已确认）。** 只有编排文件区分版本。工具按工具标识登记和查找，引用中不含工具版本。两版编排引用同一个工具标识时，M4 均按该标识取得当前登记的契约和实现。

**结果语义。** 业务结果携带工具契约规定的数据或业务结论，例如查到余额、无权查询、暂无数据。调用错误携带原因和关联信息，例如引用无效、参数错误、依赖超时或响应无效。错误的可重试性依据工具是否能安全重复及故障类别判断。M4 交回本次调用结果，M2 按场景规则确定 Execution 状态。

#### 4.4.4 核心对象关系与执行流程

**装配。** 人力扩展在 `extensions/hr/tool` 提供人员、请假余额或指标查询实现，通过 `extensions/hr/client` 适配原系统。M7 装配扩展时将契约与实现交给 M4 注册。M1 管理包含节点工具引用的场景版本，M2 运行选定版本。

**显式 TOOL 节点。** M2 从编排取得指定引用，将节点输入和可信上下文交给 M4。M4 核对范围和参数后调用对应 ToolHandler。领域扩展以调用人的可信身份向原系统请求目标对象的数据，转换结果并经 M4 交回节点。M2 据此推进场景，M1 交付最终结果。

**受控 AGENT 节点。** M2 提供本节点的工具集合、可信上下文及执行限制。M3 仅向模型展示该集合中工具的名称、用途和输入结构，可适配为 Spring AI 的 `ToolDefinition`。模型直接作答时工具调用数为零。模型发出请求时，M3 内的 `ToolCallback` 直接进入同一个 M4 调用服务，可信运行信息可由应用经 `ToolContext` 传入。M4 对回调逐次校验，原系统仍按可信身份授权。M3 按模型工具调用标识关联每项请求与结果；需继续作答时按原请求回传，达到场景终止条件时将结果交回 M2。建议每次继续模型循环或调度工具前检查 M2 提供的剩余轮次、时限和取消状态，模型调用和工具调用共享本次执行预算。

**场景交付。** F-001 中，甲的身份来自可信上下文，乙的人员标识是业务参数。查询成功后由场景检查乙的余额是否满足申请条件。明确拒绝时，两条路径均按 §4.4.1 交付固定提示并正常结束；Agent 路径应将这一业务结果直接交回场景，避免模型改写提示或再次查询。F-002 中，场景明确指标口径及条件后，指标工具从原系统接口取数并保留单位。原系统返回空结果时，场景提示当前条件下暂无数据，允许调整条件；接口故障按运行规则处理。

#### 4.4.5 运行规则、参数与验证

##### 调用边界、失败及结果核对

- 工具说明和执行校验均取本次生效编排的范围。领域扩展区分调用人和目标对象。原系统可在业务接口内鉴权，也可要求先调用授权接口；采用何种方式取决于实际接口能力。明确拒绝时停止该项查询。
- M2 依据 §4.2.8 统一控制剩余时限和重试次数。建议 M4 每次报告一次尝试结果，M3 回调及领域客户端的重试计入同一预算。仅对可安全重复的临时故障追加调用。取消或进入终态后停止新调用，迟到结果不能推进 Execution。取消已发出的原系统请求能否生效，取决于接口支持。
- 领域实现按契约区分原系统的正常值、明确拒绝、无数据及无效响应。缺少契约必需字段时返回调用错误。F-002 的空数据保留为空，不能补成零。M6 按每次实际调用关联执行、节点、工具、耗时与结果类别，供追踪具体尝试。
- **人工确认与幂等（首期范围建议）。** 首期具体工具为人员、余额和指标查询；F-001 只生成页面数据，申请提交和审批在场景范围之外。建议这些查询沿用原系统授权，遇到人员重名或口径不清时由场景追问。若以后引入改变业务状态的工具，再逐项规定确认人、确认对象、原系统支持的幂等键和结果查询方式。写操作返回不明确时，只有核对到原系统结果或具备约定的安全重试条件才可继续；具体写工具另行确认。

##### 参数及来源

| 信息 | 由谁提供、如何使用 |
| --- | --- |
| 工具范围与发起方式 | 场景版本的节点编排提供。运行时分别决定 Agent 可见集合、显式节点工具以及 M4 的检查边界。 |
| 输入、结果及安全重试条件 | 领域扩展提供工具契约和适配行为，M4 用于校验、结果表达和分类。原系统对业务数据与授权负责。 |

##### 验证预期（未执行）

| 场景 | 应观察到的结果 |
| --- | --- |
| 两版编排分别由 TOOL 和 AGENT 节点引用同一工具标识；另测登记冲突和缺失引用 | 两条路径均按工具标识定位到同一已登记实现。按拟议登记规则，同一标识登记冲突时保留已登记项；编排引用缺失时指出节点及工具标识。 |
| TOOL 指定余额查询；AGENT 分别选择查询和直接回答 | TOOL 经过 M2 → M4。模型请求查询时经过 M3 回调 → M4；直接回答时，原系统调用数为零。 |
| 模型请求范围外工具，或传入错误参数、试图替换调用人 | 前两种请求在领域实现前被拒绝。调用人始终来自可信上下文，参数中出现的身份值不能改变授权主体。 |
| 原系统允许甲查询乙，再分别测试明确拒绝 | 允许时返回乙的余额。拒绝时，两条路径均结束本次办理，Execution 为 SUCCEEDED，提示“无权查询该人员的请假余额”，无重试、无请假页面。 |
| F-002 返回有效零值、空数据、无效响应 | 分别得到带单位的零值、暂无数据的业务提示、响应无效的调用错误。 |
| 临时故障、预算耗尽、取消后迟到 | 仅安全可重复的临时故障在剩余预算内追加尝试。重试耗尽按 §4.2.8 处理，迟到结果不能改写已确定终态。 |
| Agent 请求多项工具或需要再问模型 | 各项结果与对应模型请求正确匹配，M6 可关联实际调用。达到场景终止条件、用尽轮次或已取消时，停止后续推进。 |

**实际接入待验证。** 公司网关的工具请求标识、流式参数完整性与结果回传，原系统的授权响应、空数据语义、超时及取消能力均需真实接口验证。流式请求应在完整工具参数可校验后才进入 M4。以上预期供后续验证使用。

## 本轮请审阅的取舍

1. 是否接受六个对象及四项操作，工具引用只在节点编排中配置？
2. 是否在登记编排时校验工具标识，并在工具注册表中拒绝同一标识的冲突登记？
3. 是否按上述结果分类和预算处理两条路径，并把写工具的人工确认、幂等及对账留到有具体写场景时设计？
