# 任务提案：M4_DESIGN

状态：工具调用的发起规则、M4 与领域扩展的分工、F-001 代查拒绝的处理及终态已确认。受控 AGENT 允许 M3 回调直接调用 M4。上述分工已落入候选说明书 §2.1、§4.4.1；具体接口待设计。

## 目标与依据

以 F-001 的一次查询界定 M4 的调用边界：甲为乙请假，场景需要查询乙的余额。依据为[说明书](../../../docs/baseline/specificationV2.md) §3.1.4、§3.2.1 和 §4.2.7。原系统掌管业务授权，具体接口能力未验证。

## 需要人判断

1. 人力原系统能否在同一次余额查询中校验“甲可查乙”？建议优先复用这一能力。若原系统要求先调用独立授权接口，建议由人力扩展先取得允许结果再查询余额。接口现状未知时，两种接法可继续保留为待验证项。
2. M4 应如何向 TOOL 节点表达原系统的授权拒绝？建议返回可识别的拒绝类别，由 F-001 选择面向用户的提示。具体返回契约待确认。

## M4 职责与协作

依据为[说明书](../../../docs/baseline/specificationV2.md) §2.1、§3.1.4 和 §4.2.7。负责人已确认 M4 为两条路径提供统一的工具登记、调用校验及结果返回能力。领域扩展提供具体实现。

| 环节 | M4 职责 | 协作方职责 |
| --- | --- | --- |
| 工具登记与场景引用（P-011） | 约定工具如何声明用途、输入和输出，登记契约与实现的对应关系，供场景引用。 | 领域扩展提供工具实现和契约，M7 装配扩展。M1 管理含工具引用的场景版本，M2 运行该版本的编排。 |
| 调用前校验（P-013） | 根据本次场景允许的范围检查工具引用，按契约校验参数。校验通过后将调用方的可信身份与业务参数分别传给领域扩展。 | M2 在执行 TOOL 节点时提供工具引用、输入和可信上下文。领域扩展对接原系统授权，由原系统判断调用方能否操作目标业务对象。 |
| 调用原系统（P-012） | 定位已登记的实现，按工具契约发起调用并接收结果。提供参数映射和结果转换的通用约定。 | 领域扩展负责具体字段映射和原系统接口适配。原系统提供业务数据、执行授权并应用业务规则。 |
| 返回结果与运行协作 | 向调用方交回可区分的业务结果或调用错误，提供与本次执行关联的调用信号。 | M2 根据节点结果和场景编排决定后续步骤及 Execution 状态，M1 按场景输出契约交付结果，M6 使用调用信号追踪和审计。 |

**已确认的例子。** F-001 中甲替乙请假，若原系统明确拒绝查询，场景以 `SUCCEEDED` 结束，提示甲“无权查询该人员的请假余额”。上表建议由 M4 返回授权拒绝，由 M2 依场景规则完成执行；具体返回字段仍待设计。

**待细化的职责。** §2.1 将确认、幂等和结果核对列入 M4 的范围。后续需按具体工具确定哪些操作要求用户确认、重复调用由哪一方去重，以及调用结果不明确时如何与原系统核对。

## 谁发起工具调用（已确认）

[说明书](../../../docs/baseline/specificationV2.md) §3.1.2 的 P-007 已将受控 Agent 的轮次和终止条件交给 M2。§4.3.3 的模型调用目前只返回最终载荷或失败原因，缺少对本轮工具请求及下一轮工具结果的表达。本次确认覆盖 TOOL 和 AGENT 两条路径。

| 编排配置 | 已确认的发起规则 |
| --- | --- |
| 编排未允许模型自主调用 | 需要使用工具时，由 M2 按编排调用 M4。 |
| 编排允许模型自主调用 | 模型在允许范围内自行决定是否调用、选用哪个工具，并发起工具调用请求。M4 校验请求并通过领域扩展执行。 |

同一工具的说明与实际调用共用 M4 的登记契约。可信身份从运行上下文传给 M4，模型只提供业务参数。沿用 F-001 已确认的代查拒绝结果，M2 可直接以 `SUCCEEDED` 结束并交付既定提示。

Spring AI 1.1.x 支持框架自动执行工具并再次请求模型，也支持关闭内部执行，由应用接管每轮。负责人确认受控 AGENT 允许由 M3 内的 Spring AI 回调直接调用 M4。M2 仍负责 P-007 的轮次与终止条件。普通 MODEL 节点继续按既有最终输出契约工作。若支持流式工具请求，须等请求及参数完整后执行。公司网关对请求标识、结果回传和流式拼接的支持待验证。[Spring AI 1.1 Tool Calling](https://docs.spring.io/spring-ai/reference/1.1/api/tools.html)

**§2.1 图示（已落稿）。** M3 → M4 表示受控 Agent 的 Spring AI 工具回调，M2 → M4 表示显式 TOOL 节点。两条路径的运行分工见候选说明书 §4.4.1。

## §4.4.2 核心数据模型与对象（修订讨论稿，待确认）

领域扩展定义并实现工具，场景版本的编排引用工具，M4 负责登记、校验和调用。本节对应 P-011 至 P-013，沿用[候选说明书](../../../docs/baseline/specificationV2.md) §4.4.1 已确定的两条调用路径。下列名称表示逻辑职责，具体接口签名留待后续设计。

| 对象或契约 | 归属及职责 | 核心信息或操作 |
| --- | --- | --- |
| `ToolContract` 工具契约 | M4 约定描述方式，领域扩展提供每个工具的定义。供编排引用、参数校验和结果解释共同使用。 | 工具标识、用途、输入结构和结果约定。模型可见的工具名、说明和输入结构从这份契约取得。 |
| `ToolHandler` 领域工具执行接口 | M4 约定执行入口，领域扩展提供实现。例如人力扩展在 `extensions/hr/tool` 中实现余额查询，使用 `extensions/hr/client` 对接业务和授权接口。 | 接收已通过工具契约校验的参数及所需可信上下文，映射原系统请求，将响应转换成契约约定的业务结果或调用错误。业务事实和授权决定由原系统提供。 |
| `ToolRegistry` 工具注册表 | M4 在 M7 装配领域扩展时，按工具标识登记契约及对应的执行实现。 | 按编排引用取得契约或定位实现。已登记的工具中，本节点允许哪些由当前编排给出。 |
| `ToolCallRequest` 工具调用请求 | 表达一次实际调用，两条路径共用。 | 工具引用和业务参数，以及来自运行环境的当前节点工具范围和必要的 `NodeContext` 信息，包括可信身份、执行与节点调用标识、适用时限及取消信号。 |
| `ToolInvocationService` 工具调用服务 | M4 向 M2 和 M3 回调提供统一入口。 | 检查引用是否属于当前节点允许范围，查找契约和实现，校验参数后执行。越界、查无工具或参数无效时，返回调用错误，在调用领域实现前结束。提供与本次执行关联的调用信号供 M6 使用。 |
| `ToolCallResult` 工具调用结果 | M4 向本次调用方交回业务结果或调用错误。 | 业务结果依工具契约表达，例如余额或明确的授权拒绝。依赖超时等调用错误携带可供场景判断的原因。Execution 终态由 M2 依据场景规则确定。 |

**编排如何引用工具。** 显式 TOOL 节点配置指定工具引用，受控 AGENT 节点配置允许模型自主使用的工具引用集合。以余额查询为例，领域扩展只登记一个实现。编排中的两个节点可按需引用同一工具。原稿称为 `ToolBinding` 的内容归入节点编排配置，M4 直接使用本次执行所采用版本的配置。

**两条路径如何运行。**

1. 显式 TOOL 节点：M2 取出编排指定的工具和节点输入，向 M4 提交 `ToolCallRequest`。调用服务经注册表定位领域实现，执行后将 `ToolCallResult` 交回节点。M2 按节点结果继续执行或结束。
2. 受控 AGENT 节点：M2 提供本节点允许的工具范围和运行上下文。M3 按该范围取已登记的工具说明，为模型提供相应的 Spring AI `ToolDefinition`。模型可以直接作答；若发出工具请求，M3 内的 `ToolCallback` 把工具引用、模型生成的业务参数及应用传入的可信上下文交给同一个 M4 调用服务。回调可通过 `ToolContext` 取得运行信息。需要继续推理时，M3 将工具结果按模型工具调用标识与原请求配对后回传；达到场景终止条件时，节点把结果交还 M2。轮次、时限、取消及 Execution 终态沿用 M2 的规则。Spring AI 的模型交互对象由 M3 适配。[Spring AI 1.1 工具调用文档](https://docs.spring.io/spring-ai/reference/1.1/api/tools.html)

**F-001 的结果如何交付。** 甲替乙请假时，乙的人员标识来自业务参数，甲的身份来自可信上下文。查询成功，工具返回乙的余额，场景继续判断；原系统明确拒绝，工具返回“无权查询”的业务结果，两条路径均将这一结果交给场景结束办理。M2 将 Execution 记为 `SUCCEEDED`，M1 向甲交付“无权查询该人员的请假余额”，不重试、不生成请假页面。若接口超时，返回调用错误，由 M2 按 §4.2.8 的安全重试条件、次数和剩余时限处理。

接口字段、工具版本引用、人工确认、幂等及结果核对规则待细化。真实网关和原系统接入仍待验证。
