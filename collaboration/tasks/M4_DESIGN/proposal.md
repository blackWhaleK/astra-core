# 任务提案：M4_DESIGN

状态：工具调用的发起规则、M4 与领域扩展的分工、F-001 代查拒绝的处理及终态已确认。模型工具请求的运行接法与接口契约待定。

## 目标与依据

以 F-001 的一次查询界定 M4 的调用边界：甲为乙请假，场景需要查询乙的余额。依据为[说明书](../../../docs/baseline/specificationV2.md) §3.1.4、§3.2.1 和 §4.2.7。原系统掌管业务授权，具体接口能力未验证。

## 需要人判断

1. 人力原系统能否在同一次余额查询中校验“甲可查乙”？建议优先复用这一能力。若原系统要求先调用独立授权接口，建议由人力扩展先取得允许结果再查询余额。接口现状未知时，两种接法可继续保留为待验证项。
2. M4 应如何向 TOOL 节点表达原系统的授权拒绝？建议返回可识别的拒绝类别，由 F-001 选择面向用户的提示。具体返回契约待确认。

## M4 职责与协作

依据为[说明书](../../../docs/baseline/specificationV2.md) §2.1、§3.1.4 和 §4.2.7。负责人已确认 M4 为两条路径提供统一的工具登记、调用校验及结果返回能力。领域扩展提供具体实现。

| 环节 | M4 职责 | 协作方职责 |
| --- | --- | --- |
| 工具登记与场景引用（P-011） | 约定工具如何声明用途、输入和输出，登记契约与实现的对应关系，供场景引用。 | 领域扩展提供工具实现和契约，M7 装配扩展。M1 管理含工具引用的场景版本，M2 运行该版本的编排。 |
| 调用前校验（P-013） | 根据本次场景允许的范围检查工具引用，按契约校验参数。校验通过后将调用方的可信身份与业务参数分别传给领域扩展。 | M2 在执行 TOOL 节点时提供工具引用、输入和可信上下文。领域扩展对接原系统授权，由原系统判断调用方能否操作目标业务对象。 |
| 调用原系统（P-012） | 定位已登记的实现，按工具契约发起调用并接收结果。提供参数映射和结果转换的通用约定。 | 领域扩展负责具体字段映射和原系统接口适配。原系统提供业务数据、执行授权并应用业务规则。 |
| 返回结果与运行协作 | 向调用方交回可区分的业务结果或调用错误，提供与本次执行关联的调用信号。 | M2 根据节点结果和场景编排决定后续步骤及 Execution 状态，M1 按场景输出契约交付结果，M6 使用调用信号追踪和审计。 |

**已确认的例子。** F-001 中甲替乙请假，若原系统明确拒绝查询，场景以 `SUCCEEDED` 结束，提示甲“无权查询该人员的请假余额”。上表建议由 M4 返回授权拒绝，由 M2 依场景规则完成执行；具体返回字段仍待设计。

**待细化的职责。** §2.1 将确认、幂等和结果核对列入 M4 的范围。后续需按具体工具确定哪些操作要求用户确认、重复调用由哪一方去重，以及调用结果不明确时如何与原系统核对。

## 谁发起工具调用（已确认）

[说明书](../../../docs/baseline/specificationV2.md) §3.1.2 的 P-007 已将受控 Agent 的轮次和终止条件交给 M2。§4.3.3 的模型调用目前只返回最终载荷或失败原因，缺少对本轮工具请求及下一轮工具结果的表达。本次确认覆盖 TOOL 和 AGENT 两条路径。

| 编排配置 | 已确认的发起规则 |
| --- | --- |
| 编排未允许模型自主调用 | 需要使用工具时，由 M2 按编排调用 M4。 |
| 编排允许模型自主调用 | 模型在允许范围内自行决定是否调用、选用哪个工具，并发起工具调用请求。M4 校验请求并通过领域扩展执行。 |

同一工具的说明与实际调用共用 M4 的登记契约。可信身份从运行上下文传给 M4，模型只提供业务参数。沿用 F-001 已确认的代查拒绝结果，M2 可直接以 `SUCCEEDED` 结束并交付既定提示。

Spring AI 1.1.x 支持框架自动执行工具并再次请求模型，也支持关闭内部执行，由应用接管每轮。模型发起请求后，可由 M3 内的回调调用 M4，也可由 M3 将请求交给 M2 转调 M4。具体接法待定，设计时需说明如何落实 P-007 的轮次与终止条件。普通 MODEL 节点继续按既有最终输出契约工作。若支持流式工具请求，须等请求及参数完整后执行。公司网关对请求标识、结果回传和流式拼接的支持待验证。[Spring AI 1.1 Tool Calling](https://docs.spring.io/spring-ai/reference/1.1/api/tools.html)

**§2.1 图示建议（待确认）。** 若 M2 逐轮推进受控 Agent，沿用 M2 → M3、M2 → M4 两条实线。在图下说明：M3 把模型提出的工具请求交回 M2，M2 调用 M4；需要模型继续作答时，M2 将工具结果交给 M3。若改由 M3 内的 Spring AI 回调直接调用 M4，则增加 M3 → M4 实线，标注“模型请求触发的工具调用”，同时保留 M2 → M4 表示编排指定的 TOOL 节点。
