## §4.2.1 职责与协作

用户提出的职责方向为 M1 传入场景信息，M2 负责执行并按需调用 M5、M4、M3，M6 收集并记录执行过程的运行信息。

已确认的分工为 M1 提供选定的场景及版本，由场景版本确定 Node 的调用顺序。M2 预先定义 Node 类型，并由 Runner 按场景编排运行 Node、推进流程及管理 Execution 状态。M2 不自行选择整体执行策略。并行 Node、循环 Node 和 ReAct Node 是用户提出的例子，具体契约待细化。

场景可配置具备运行时选择能力的 Node。例如，循环 Node 可以调用 M3，由模型根据当前运行结果判断是否推进到编排指定的下一个 Node。Runner 根据判断结果推进流程。模型判断暂不推进时的循环行为待讨论。

执行过程按需使用其他模块的能力。需要知识检索或文档解析时调用 M5，需要业务工具时调用 M4，需要提示词或模型处理时调用 M3。建议 M2 将执行结果交给 M1 对接调用方。

建议 M2 提供可关联到同一次 Execution 的运行信号，例如开始、结束、关键步骤结果状态、耗时和错误分类。M6 将运行信号用于审计、追踪和监控。具体采集字段及接口待细化。

待讨论循环 Node 在模型判断暂不推进时的行为，以及循环退出和达到运行上限时的结果。

## §4.2.2 核心数据模型、对象

状态：用户已明确同意落稿。以下对象定义、最小信息和操作记录说明已写入 V2 §4.2.2，§2.1 的 Step 表述已删除。

| 对象 | 定义 | 最小信息或职责 |
| --- | --- | --- |
| Node | 场景版本中配置的一个节点。M2 预定义 Node 类型及其行为，场景版本确定使用哪些 Node、如何配置及如何连接。 | 节点标识、节点类型、节点配置。Runner 运行节点时提供该节点所需的输入，接收节点输出及可供场景编排使用的判断结果。 |
| Execution | M2 按一个选定的场景版本发起的一次执行。执行期间使用启动时选定的场景版本。 | 执行标识、场景及版本、关联的 Session、本次输入、执行状态、临时上下文和最终结果。临时上下文包含当前节点运行状态、中间结果，以及等待输入时的待补充内容和续接位置。 |
| Session | 保存场景会话上下文的临时对象。多轮对话中的多个 Execution 共享同一个 Session。一次性调用的 Session 随当次 Execution 结束。 | 会话标识、会话上下文、当前未结束 Execution 的关联标识及有效期信息。多轮对话可保存对话消息、查询条件和用户选择。 |
| Runner | M2 中负责推进 Execution 的运行组件。 | 接收 M1 提供的场景、版本和输入，根据该版本的编排及 Node 返回的结果调度后续节点，维护 Execution 状态，向 M1 返回结果。 |

Node 在场景版本内定义。同一个 Node 可以在一次 Execution 中运行多次。Runner 在本次 Execution 的临时上下文中区分各次运行，首期暂缓将这些运行建模为独立的 Step 对象。Execution 的临时上下文服务于本次执行，Session 的会话上下文供关联的 Execution 使用。会话及执行记录均遵守首期不持久化的约束。

M6 使用通用记录器逐次记录工具调用和模型对话。运行信号可以携带关联标识，用于串联同一次 Execution 的操作。例如，一个循环 Node 每轮调用一次工具和一次模型，执行两轮后可以分别追踪四次操作。记录器的字段和接口留待 M6 细化。

Execution 的状态转换见 §4.2.3，节点类型的控制规则、并行结果汇聚及循环退出留待 §4.2.5 讨论。对象字段名、类型和对外结构留待 §4.2.7 细化。

## §4.2.3 Execution 生命周期

状态：用户已明确要求将本轮讨论写入 V2。以下生命周期、SSE 分离、Session 续接和缓存空闲 8 小时过期规则已落稿。具体执行超时和结果清理仍待设计。

Runner 统一维护 Execution 的生命周期，根据状态决定是否继续调度 Node、是否接受关联的补充输入，以及何时结束执行。

### 状态定义

| 状态 | 含义与进入条件 |
| --- | --- |
| RUNNING | Runner 正在推进执行，涵盖节点运行、模型及工具调用等待、编排内的循环与重试。 |
| WAITING_INPUT | 当前执行需要用户补充条件或选择口径，Runner 保存续接所需的临时上下文，等待关联回复。 |
| SUCCEEDED | 场景流程按约定完成并形成最终结果，包括正常的业务提示。 |
| FAILED | 执行遇到无法按场景约定处理的错误，适用的重试已耗尽，或执行达到配置的超时等失败条件。 |
| CANCELLED | 用户手动结束，Runner 已停止后续调度并确认本次执行结束。 |

RUNNING 和 WAITING_INPUT 为未结束状态。SUCCEEDED、FAILED 和 CANCELLED 为终态。

### 启动

Runner 接收 M1 提供的场景及版本、本次输入和 Session 关联信息，校验启动条件。同一 Session 存在未结束的 Execution 时，新独立问题暂不启动执行。通过校验后创建 Execution，固定场景版本，进入 RUNNING 并开始调度。启动条件不满足时向 M1 返回相应提示。

### 运行与等待输入

RUNNING 下按场景编排推进 Node。模型或工具调用等待、循环内继续执行、允许范围内的重试均维持 RUNNING。

需要用户澄清或选择时，Runner 保存待补充内容、下一步执行位置和所需的中间结果，进入 WAITING_INPUT，并通过 M1 提示用户。等待期间可接受与当前 Execution 关联的补充回复或取消请求。新的独立问题须在当前执行结束后发起。

回复满足本次补充要求后，Runner 更新当前执行的输入和临时上下文，使用同一 executionId、Session 和场景版本回到 RUNNING。回复仍不足时，保持 WAITING_INPUT 并继续提示。关联的回复应仅被接纳一次，避免重复提交触发重复续接。

### 完成与失败

场景流程按约定完成，Runner 确定最终结果并进入 SUCCEEDED。例如查询正常返回“暂无数据”可以完成本次执行。

出现无法继续处理的异常、适用重试耗尽或配置的执行时限到达时，Runner 进入 FAILED，保存失败原因及可返回的提示。执行时限以及等待输入是否另设超时、采用何种时限，留待运行参数设计。

### 取消与终态竞争

RUNNING 和 WAITING_INPUT 均可响应用户手动结束。Runner 接受取消后停止后续调度，按依赖提供的能力尝试终止在途调用，并确定 CANCELLED。

成功、失败、取消或超时并发到达时，Runner 只确认一次终态，并同时确定对应结果。终态确定后的迟到调用结果不再更新当前执行、写入会话或触发后续 Node。依赖侧调用的实际终止能力留待接入验证。

SSE 负责本轮输出传输，每轮输出完成后关闭。发完追问后关闭 SSE，Execution 保持 WAITING_INPUT。SSE 的连接生命周期独立于 Execution，状态转换由 Runner 根据执行结果、关联回复、显式取消或配置的超时条件决定。

### 通过 Session 续接

Session 保存当前未结束 Execution 的关联标识，Execution 保存实际状态及续接所需的场景版本、待补充内容、执行位置和中间结果。新请求携带同一 Session 标识，由服务端核对会话归属并找到当前 Execution。处于 WAITING_INPUT 时，Runner 校验关联回复，符合要求后将同一 Execution 推进至 RUNNING。Execution 结束时更新 Session 中的当前执行关联。

Session 的会话上下文、当前执行关联和 Execution 的续接信息需要跨请求保留。Runner 应先保存等待状态和续接信息，再输出追问，接收回复时保证同一次续接只生效一次。

用户已确认 Session 和 Execution 的临时状态使用缓存保存，有效期为 8 小时，以支持服务运行期间的跨请求续接。页面刷新或重新打开时，只要能够找回原 Session 标识且服务端状态仍有效，即可关联原会话和当前执行。后端服务重启后允许会话失效，提示用户重新发起。

用户已确认按最近一次有效对话重新计时，连续 8 小时无有效对话后过期。Session 与当前 Execution 的续接状态保持有效期一致。缓存过期后的请求提示会话失效，执行超时和等待输入超时仍需分别设计。

### 结束后的处理

进入终态后，向 M1 提供结果或结束原因，解除当前 Execution 对新独立问题的限制，并清理运行资源。自然完成、失败或取消后均可直接提出下一问。

多轮 Session 保留供后续执行使用的会话上下文，一次性调用的 Session 随 Execution 结束。执行内部的临时节点状态按资源清理规则释放。终态结果的短期可获取范围及清理时点留待接口和运行参数设计。

后端重启导致 Session 或其关联的 Execution 状态丢失时，后续访问提示“会话已失效，请重新发起”，由用户开始新的会话和执行。原执行的具体终态以实际可用记录为依据，状态丢失本身仅能确定其已不可继续访问。

### 状态转换

| 当前状态 | 触发条件 | 目标状态 |
| --- | --- | --- |
| 启动校验通过 | 创建执行并开始调度 | RUNNING |
| RUNNING | 需要用户补充或选择 | WAITING_INPUT |
| WAITING_INPUT | 关联回复满足要求 | RUNNING |
| RUNNING | 场景按约定完成 | SUCCEEDED |
| RUNNING / WAITING_INPUT | 无法继续的错误或适用超时 | FAILED |
| RUNNING / WAITING_INPUT | 用户手动结束 | CANCELLED |
| 任一终态 | 迟到结果、重复取消或重复回复 | 保持原终态 |
