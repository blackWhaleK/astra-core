## 当前已确认结论

### Execution 与业务场景

- 一个 Execution 对应一次业务任务。F-001 每次独立请求新建执行，一次性返回页面数据或业务提示。
- F-002 一次查询可以跨多轮补充。追问或选择口径期间保留原执行，用户回复后继续。
- F-002 查询完成后的追查在同一 Session 新建执行，可沿用仍适用的条件。等待补充时明确换题则关闭原查询，为新查询创建执行。
- F-003 沿用一次上传报告、一次性返回检查结果的范围。用户确认必需分项发生技术调用失败且重试耗尽时，整次执行失败并停止剩余工作。业务上的无法判断作为检查结论参与汇总。

### 六种执行状态

| 状态 | 已确认含义 |
| --- | --- |
| RUNNING | 正在处理，包括依赖调用及有限重试 |
| WAITING_FOR_INPUT | F-002 返回追问或选项后等待补充 |
| COMPLETED | 已形成最终业务结果或说明 |
| FAILED | 技术错误导致任务无法完成，必要重试已耗尽 |
| CANCELLED | 主动取消、处理中异常断线或等待时换题导致执行关闭 |
| EXPIRED | F-002 等待补充时所属会话空闲过期 |

完成、失败、取消和过期为终态。余额不足、暂无数据、报告不满足要求或无法判断等业务结果，可以随执行正常完成。

### 输入、取消、断线与保留期

- F-002 系统处理期间禁用输入，返回追问后恢复输入。处理中仍可操作停止按钮。
- 主动取消结束当前 Execution，保留已有会话，停止后续推进并尝试取消在途调用，迟到结果退出处理。
- 服务端检测到处理中的响应连接异常断开后终止当前执行，保留已有会话。重连后先核对状态，已中断时由用户重新发起。
- 等待补充期间离开页面，按会话有效期保留原执行。
- Session 连续无交互 8 小时后过期。系统返回追问或结果后开始计时，用户继续对话并完成下一次回复后重新计时。过期时关闭等待中的执行并释放相关临时上下文。

### 当前对象模型方向

- 用户已接受 F-002 使用 Execution 生命周期和查询上下文接续任务，流程节点作为内部处理环节，取代独立 Step 对象与第二套生命周期。
- 此前确认过的 F-001 处理职责仍可作为内部流程依据，包括理解请求、校验分流、按需查询人员和余额、判断条件及组装结果。
- 将简化模型统一用于 F-001、F-003 的方案已整理。用户明确确认了 F-003 失败规则，通用对象模型的最终取舍在 4.2.2 中汇总确认。
