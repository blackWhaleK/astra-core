# 任务提案：module_design

状态：部分业务取舍已确认，其他方案待确认；尚待用户同意落入候选说明书。

## 目标与依据

讨论 M1—M7 的模块职责与协作契约，首轮从 M2 的执行和会话边界切入。依据[说明书 V2](../../../docs/baseline/specificationV2.md)第 2.1、2.3、3.1 和 3.2 节。M1 仅场景定义与管理需求完成，M2 对象关系、状态机及恢复能力待设计。首期会话和执行记录不持久化，通用底座保持领域独立。

## 需要人判断

1. F-002 返回追问或选项后，原 Execution 进入等待。用户明确换题时关闭原查询；等待超时、主动取消的处理以及状态命名待确定。
2. SSE 网络断开后，是立即结束当前执行，还是允许在既定时限内跑完？若选择后者，还需明确调用方是否需要在重连后取回结果。

## 模块设计讨论顺序（待确认）

| 轮次 | 模块 | 本轮应明确的契约 |
| --- | --- | --- |
| 1 | M2 执行与上下文，连同 M1 调用边界 | 请求、会话、执行、步骤的关系，状态与终止语义，短期上下文归属。用 F-002 的追问和选口径检验跨轮衔接 |
| 2 | M3 模型与提示词，再补齐 M1 接入 | 区分模型增量与结构化结果，定义输出校验和失败。随后确定 REST/SSE 的请求、事件、终态、取消、断线和结果交互 |
| 3 | M2 编排策略、M4 工具与业务连接 | YAML 与节点契约、条件、并行汇聚和受控 Agent 的边界。用 F-001 校验可信身份、授权、超时、重试及工具调用结果 |
| 4 | M5 知识与检索 | 文档导入、解析、索引更新、检索范围与引用。用 F-003 区分知识入库和报告临时处理，用 F-002 核对指标口径检索 |
| 5 | M6 治理与质量、M7 扩展与基础设施 | 审计与追踪事件、限额与错误分类、验证样例，以及领域装配、配置、命名空间、存储适配和部署边界 |

第一轮同步对齐影响接口的横切约束，包括可信身份如何传递、追踪如何关联、超时和重试由谁控制、数据由谁持有和释放。各模块在讨论中细化自身契约，最后由 M6、M7 汇总公共机制。

## 每轮讨论深度（待确认）

- 明确职责和依赖方向，关联说明书中已有的 P 编号及涉及的 F 场景。

- 对影响契约的实现选择记录取舍。类和方法签名、完整表结构、依赖补丁版本及具体调优值留待工程设计或验证。
